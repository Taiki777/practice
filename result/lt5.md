UIをデザイン4原則で見てみる

# 想定時間

5〜10分

## この発表の目的

最近、業務でUI改善の修正を行う機会がありました。

その中で、UIは「なんとなく見やすい」「なんとなく使いづらい」と感覚で判断しがちだと感じました。

デザインの4原則を使って、

自社プロダクトの画面を見てみます。

今回扱う4原則は以下です。

| 原則 | 内容 |
| --- | --- |
| 近接 | 関連する情報を近くに置く |
| 整列 | 要素の位置を揃える |
| 反復 | 同じ意味の要素に同じ見た目を使う |
| コントラスト | 重要な情報を目立たせる |

---

# 1. 近接

## 近接とは

近接とは、**関連する情報同士を近くに配置すること**です。

人は、近くにある要素を「関係があるもの」として認識しやすいです。

そのため、関連する情報が近くにまとまっていると、

どの情報がどこに紐づいているのか分かりやすくなります。

逆に、関連する情報が離れていると、

ユーザーは「これは何に対する説明なのか」「どの入力欄に対するエラーなのか」を考える必要があります。

## UIでの例

例えばフォーム画面では、以下のような要素は近くにある方が分かりやすいです。

- ラベル
- 入力欄
- 補足説明
- エラーメッセージ

```
メールアドレス
[                    ]
メールアドレスの形式が正しくありません
```

このように、入力欄とエラーメッセージが近いと、

どの項目でエラーが起きているのか分かりやすくなります。

## 自社プロダクトの画面では

【ここに自社プロダクトの画面キャプチャを貼る】

例：

自社プロダクトの画面では、関連する項目がまとまって配置されています。

例えば、フォーム画面では、項目名・入力欄・補足説明が近くに配置されているため、

どの入力欄に対する説明なのかが分かりやすくなっています。

また、検索条件エリアや設定項目なども、関連する情報ごとにまとまっているため、

画面全体の構造を把握しやすくなっています。

# 2. 整列

## 整列とは

整列とは、**要素の位置を揃えること**です。

画面上の要素の開始位置や幅が揃っていると、

視線の流れが自然になり、情報を追いやすくなります。

逆に、要素の位置がバラバラだと、

視線が左右に動きやすくなり、画面が整理されていない印象になります。

## UIでの例

例えば、以下のように入力欄の開始位置が揃っていると、上から順に確認しやすくなります。

```
名前
[                    ]

メールアドレス
[                    ]

電話番号
[                    ]
```

また、一覧画面では、テーブルの列が揃っていることで、

同じ種類の情報を縦に比較しやすくなります。

## 自社プロダクトの画面では

【ここに自社プロダクトの画面キャプチャを貼る】

例：

自社プロダクトの画面では、フォームの入力欄やボタンの位置が揃えられています。

また、一覧画面では、テーブル形式で情報が表示されており、

項目ごとに列が揃っているため、複数のデータを比較しやすくなっています。

例えば、ステータス、作成日時、更新日時、操作ボタンなどが列として揃っていると、

ユーザーは必要な情報を横方向・縦方向に追いやすくなります。

# 3. 反復

## 反復とは

反復とは、**同じ意味や役割を持つ要素に、同じ見た目を繰り返し使うこと**です。

同じ役割のものが同じ見た目になっていると、

ユーザーは一度理解したルールを別の画面でも使えます。

例えば、ある画面で「青いボタン」が主要な操作を表している場合、

別の画面でも同じルールで使われていると、ユーザーは迷いにくくなります。

## UIでの例

反復が使われる要素には、以下のようなものがあります。

- ボタン
- ラベル
- エラーメッセージ
- ステータス表示
- アイコン
- テーブル
- モーダル

例えば、保存ボタンの文言や見た目が画面ごとに大きく違うと、

ユーザーは毎回その意味を判断する必要があります。

```
画面A：保存
画面B：保存
画面C：保存
```

このように同じ操作に同じ表現を使うことで、

画面全体に統一感が出ます。

## 自社プロダクトの画面では

【ここに自社プロダクトの画面キャプチャを貼る】

例：

自社プロダクトでは、同じ役割のUI部品が複数の画面で繰り返し使われています。

例えば、一覧画面のテーブル、検索条件エリア、操作ボタン、ステータス表示などは、

画面が変わっても似た構成で表示されています。

そのため、一度画面の見方を理解すると、

別の画面でも同じような感覚で操作しやすくなっています。

また、ボタンやラベルの見た目が統一されていることで、

どれが操作できる要素なのか、どれが状態を表す要素なのかを判断しやすくなっています。

# 4. コントラスト

## コントラストとは

コントラストとは、**重要な情報とそうでない情報に差をつけること**です。

すべての要素が同じ強さで表示されていると、

ユーザーはどこを見ればよいのか分かりにくくなります。

重要な情報は目立たせ、補足的な情報は少し控えめにすることで、

画面の中で優先して見るべき場所が分かりやすくなります。

## UIでの例

コントラストが使われる場面には、以下のようなものがあります。

- 主要ボタン
- 警告メッセージ
- エラーメッセージ
- 見出し
- ステータス
- 必須項目
- 重要な数値

例えば、保存ボタンとキャンセルボタンが同じ強さで表示されていると、

どちらが主要な操作なのか分かりにくくなる場合があります。

```
[保存]   キャンセル
```

このように、主要な操作と補助的な操作に差をつけることで、

ユーザーが次に何をすればよいか判断しやすくなります。

## 自社プロダクトの画面では

【ここに自社プロダクトの画面キャプチャを貼る】

例：

自社プロダクトの画面では、主要な操作ボタンやステータス表示などにコントラストが使われています。

例えば、登録・保存・実行などの主要な操作は、

他の補助的な操作よりも目立つように表示されています。

また、エラーや警告など、ユーザーに気づいてほしい情報は、

通常のテキストとは異なる見た目で表示されるため、重要度が伝わりやすくなっています。
